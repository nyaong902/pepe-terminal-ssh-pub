# v2.3.9

**vi 화면이 이전 내용과 겹쳐 보이던 문제를 고쳤습니다.** 2.3.6 부터 생긴 것으로, 서버나 창 크기에
따라 어떤 사람에게는 늘 보이고 어떤 사람에게는 한 번도 안 보였습니다. 원격 공유는 WebRTC 로
바뀌었고, 설치할 때 선택할 수 있게 됐습니다.

## 🖥 vi 화면이 겹쳐 보이던 문제

`vi` 를 열면 **실행 전 화면이 지워지지 않고 남아** vi 화면과 겹쳐 보였습니다. `top`, `less` 처럼
화면 전체를 쓰는 프로그램도 같았습니다.

2.3.6 에서 로그 폭주 시 CPU 를 줄이려고 "밀린 출력의 앞부분을 버리는" 처리를 넣은 것이 원인입니다.
터미널 출력에는 **화면을 지우라거나 커서를 어디로 옮기라는 지시**가 섞여 있는데, 앞부분을 버리면
그 지시가 함께 사라집니다. vi 는 화면 전체를 그리는 출력이 커서 그 기준을 넘었고, 결과적으로
"지우라는 말"이 사라져 이전 화면이 남았습니다.

> **왜 어떤 서버에서는 정상이었나** — 기준이 크기(6KB)였기 때문입니다. 화면이 넓을수록 vi 가 보내는
> 양이 많아지므로, 같은 서버라도 창을 좁히면 정상이고 최대화하면 겹쳤습니다. 서버 설정(vim 버전,
> 색상, TERM)이 완전히 같은 두 장비에서 한쪽만 증상이 나온 것도 이 때문입니다.

이제 **화면 배치를 바꾸는 지시가 섞여 있으면 한 바이트도 버리지 않습니다.** 순수한 로그 흐름
(`tail -f` 등)만 예전처럼 정리해서 CPU 를 아낍니다 — 폭주 시 CPU 는 그대로 낮게 유지됩니다.

## 📜 분할창을 오갈 때 스크롤이 맨 아래로 튀던 문제

로그를 위로 올려 읽는 중에 다른 분할창을 눌렀다 돌아오면 **화면이 맨 아래로 내려가** 읽던 자리를
잃었습니다. 이제 보던 위치가 유지됩니다. 맨 아래를 보고 있었으면 예전처럼 새 출력을 따라갑니다.

## 🔎 vi 안에서 위로 스크롤하면 이전 화면 보기 (새 옵션)

`vi`/`less`/`top` 안에서는 마우스 휠을 올려도 아무 일이 없었습니다. 이제 XShell 처럼 **그 프로그램을
실행하기 전 화면**을 거슬러 볼 수 있습니다. 세션 편집 > **고급 > 스크롤** 에서 켜세요(기본 꺼짐).

굴리면 이전 내용이 위에서 밀려 들어오고 vi 화면은 아래로 밀려납니다 — 두 화면이 이어져 보이므로
어디까지가 이전 내용인지 바로 알 수 있습니다.

- 스크롤해서 이전 내용을 보고, **드래그해서 복사**할 수 있습니다
- 아무 키를 누르거나, 아래로 끝까지 굴리면 원래 화면으로 돌아옵니다
- `Ctrl+C` 같은 복사 조합은 닫히지 않습니다 (복사가 이 기능의 주된 용도라서입니다)

## 📡 원격 공유 — WebRTC 로 바뀌고, 설치 시 선택할 수 있습니다

화면 전송이 **WebRTC** 방식으로 바뀌어 지연이 크게 줄었습니다. 입력도 같은 연결로 전달됩니다.
방화벽에 막히는 환경을 위해 기존 방식(MJPEG)도 남겨두고 공유를 시작할 때 고를 수 있습니다.

확대/축소, 전체화면, 확대 상태에서 화면 끝으로 밀어 이동하기가 추가됐고, 원격에서 키보드 입력이
일부 화면에 전달되지 않던 문제도 함께 고쳤습니다.

**설치 프로그램에 "원격 공유" 항목이 생겼습니다.** 해제하면 메뉴에서 숨겨지고 관련 파일도 설치되지
않습니다.

## 💬 대화 아카이브 — 방 이름과 검색

- 방 이름이 **설치본과 개발 환경에서 서로 안 보이던 문제** 를 고쳤습니다(저장 위치를 앱 데이터로 옮김)
- 로그인 직후에 방이 일부만 잡히던 것을 백그라운드로 미리 읽어 보완했습니다
- 방을 전환할 때 반응하지 않던 경우를 고쳤습니다
- 메신저 화면에 **새로고침 / 처음으로** 버튼이 생겼습니다
- 큰 대화를 요약할 때 시간이 모자라 잘리던 것을 넉넉하게 늘렸습니다

## ⌨ 세션 검색 후 Enter 로 목록으로 이동

세션을 검색한 뒤 Enter 를 눌러도 목록으로 포커스가 가지 않던 문제를 고쳤습니다. 접힌 폴더가 있어도
화면에 보이는 순서대로 내려갑니다.

## 🔐 접속할 때 협상된 암호를 보여줍니다

```
▶ xxx.xxx.xxx.xxx:22 (root) 연결 중...
  [handshake OK · aes128-gcm]
```

서버와 합의한 암호 방식이 접속 줄에 함께 나옵니다. 로그가 쏟아질 때 CPU 는 대부분 이 암호 처리에
쓰이므로, 느릴 때 서버 설정 문제인지 판단하는 근거가 됩니다(`aes*-gcm`/`aes*-ctr` 은 하드웨어 가속을
타고, `chacha20-poly1305` 는 몇 배 느립니다).
