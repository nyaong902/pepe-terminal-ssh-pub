# v2.6.7

**터미널을 많이 열어도 메모리가 불지 않게** 손봤고, **AI Chat 승인 판정**을 다시 짰습니다.
파일 비교에는 **소스/타겟을 따로 고르는 숨김**과 **빈 비교**가 들어갔고, `ctcocr`/`ctcicr` 가
`CLEARCASE_ROOT` 오류로 실패하던 것을 고쳤습니다. 두 PC 사이에서 **AI 채팅을 메시지 단위로 합치는**
동기화, 모바일 채팅(Tailscale)·텔레그램 알림, 대화방 단위 **매크로**도 이번에 들어갔습니다.

## 🧠 메모리와 CPU

"메모리를 너무 쓴다"는 제보를 프로세스 → 스레드 → 함수 순으로 좁혀 가며 원인을 찾았습니다.

- **스크롤백이 메모리를 먹지 않게** — 터미널 하나가 500만 줄을 쥐고 있어 렌더러가 11.8GB 에서
  죽은 사례가 있었습니다. 터미널 하나의 상한이 **10만 줄**(기본 5,000줄)이고, 화면에 올라온
  터미널 전체가 나눠 쓰는 예산이 256MB 입니다. 열린 수가 늘면 각자의 몫이 줄 뿐 전체는 그 선을
  넘지 않습니다. 이미 저장된 큰 값도 불러올 때 상한에 맞춥니다
- **닫은 터미널이 안 죽던 누수** — 닫은 뒤에도 xterm 인스턴스 57개가 살아 있었습니다
- **숨은 탭이 압축되지 않던 것** — 배경 탭이 전부 "보이는 것"으로 세어졌습니다. 이제 실제로
  화면에서 벗어난 탭만 압축하고, 돌아올 때 화면이 움직이던 것도 함께 잡았습니다
- **렌더러가 시간당 80MB 씩 불던 것** — 머메이드 그림의 pan/zoom 리스너 정리 누락 등 세 자리를
  막았습니다. 65시간 켜 둔 앱에서 재 보니 +81 → +11 MB/h 로 줄었습니다
- **SSH 터미널이 워커를 나눠 씁니다** — 패널마다 워커를 하나씩 띄우던 것을, 워커 하나가 세션
  여럿을 맡도록 바꿨습니다(상한은 코어 수에 맞춤). 주 프로세스 메모리가 터미널 16개 기준
  605MB → 333MB(유휴) 로 줄었습니다(같은 세션 수로 환산하면 약 230MB 절감)
- **출력이 쏟아질 때 CPU** — AES-GCM 복호화를 Windows 네이티브(CNG)로 돌리고, 전부 ASCII 인 출력은
  인코딩 변환을 건너뜁니다. 같은 조건에서 워커 CPU 가 약 **1.8배** 줄었습니다
- 자동 인코딩 판정이 한번 CP949 로 넘어가면 UTF-8 한글이 영원히 깨지던 것을 고쳤습니다
- 앱을 켤 때 Temp 폴더의 찌꺼기를 한 번 정리합니다(이름으로 고른 목록만, 3일 지난 것만)
- 분리창이 AI 사이드바와 메신저를 같이 띄워 창마다 100MB 가 더 붙던 것을 막았습니다
  (분리창 DOM 4,014 → 878 노드). AI Chat·메신저는 메인 창에서 씁니다
- 빌드가 위 성능 구조를 지키는지 검사합니다(`verify-ssh-perf`). 되돌아가면 빌드가 멈춥니다

## 🤖 AI Chat

- **승인 판정을 읽기 / 쓰기 / 모름 세 갈래로** 다시 짰습니다
  - 따옴표 안의 `|` 를 파이프로 쪼개 `grep 'a\|b'` 같은 조회까지 막히던 것을 고쳤습니다
  - `sed -n`, `awk` 같은 순수 조회는 승인 없이 통과합니다. 파일을 건드리는 형태(`sed -i`, `w`
    명령, `awk` 의 `print >` · `system()`)는 계속 승인을 묻습니다
  - `ls & rm -rf /` 가 통째로 `ls` 로 취급되던 구멍을 막았습니다
  - 모르는 명령(사내 스크립트 등)은 여전히 승인을 묻습니다
- **"권한 요청 + 툴별 승인"인데 묻지 않고 파일을 만들고 지우던 것**, **읽기만 하는 `ssh_exec` 까지
  승인을 묻던 것**을 고쳤습니다
- **승인 카드가 그 승인이 속한 대화에만** 뜹니다. 다른 대화를 읽는 중에 남의 승인창이 올라오던 것을
  막았습니다. 다른 대화로 갔다면 그 대화와 미니탭에 🖐 가 뜨고, 그곳으로 가면 카드가 있습니다
- 대화를 옮겼다 돌아오면 **보던 자리로** 돌아옵니다
- AI Chat 과 터미널에 **"맨 아래로" 단추**가 생겼습니다. 위로 올려 읽을 때만 파란 ↓ 로 뜹니다
- Claude **플랜 사용률**이 CLI 를 한 번 띄운 뒤에야 보이던 것을, 저장된 갱신 토큰으로 바로
  가져오도록 했습니다
- 다른 PC 에서 동기화된 방에 이 PC 의 CLI 세션이 없을 때, 대화 전체를 앞에 붙여 `Prompt is too long`
  으로 실패하던 것 — 이제 가장 최근 12만 자만 보냅니다
- 긴 AI 방을 위한 **누적 대화 기억**이 들어갔습니다

## 🗂 파일 비교

- **한쪽에만 있는 항목 숨김을 소스 / 타겟 따로** 고릅니다. 타겟만 체크하면 소스에 새로 추가된
  파일은 계속 보이고 타겟에만 남은 파일만 숨겨집니다(예전 저장값은 둘 다 체크로 읽습니다)
- **📝 빈 비교** — 파일을 열지 않고 양쪽 빈 편집기에 문구를 붙여 넣어 비교합니다. 경로가 비어
  있으면 저장은 막히고 다운로드만 됩니다
- **`ctcocr` / `ctcicr` 가 `CLEARCASE_ROOT: Undefined variable` 로 실패하던 것**을 고쳤습니다.
  실행 채널에서는 뷰가 걸려 있지 않아서였습니다. 이제 경로나 세션의 뷰를 찾아 `setview -exec` 로
  감싸 실행하고, 결과에서 `stty: standard input: Invalid argument` 잡음은 걸러 냅니다
- ClearCase 체크아웃 상태(CO/CI)를 **폴더 단위로** 읽습니다. 큰 트리에서 60초 제한에 걸려 배지가
  조용히 사라지던 것을 줄였습니다
- 파일 비교와 파일 전송을 **매크로**로 기록하고 재생합니다

## ⏺ 매크로

- 앱 동작을 **대화방별로 기록하고 다시 재생**합니다
- AI 가 값만 바꿔 한 번 돌려 주고, 매크로를 **내보내기 / 가져오기** 합니다(저장 오류도 고쳤습니다)
- AI 가 **한 번에 실행**하는 모드, 미니탭 고르기가 들어갔습니다

## 📱 채팅 · 백업

- **모바일 채팅(Tailscale)**, **텔레그램 알림**, **하위 에이전트 패널**이 들어갔습니다
- **두 PC 사이 AI 채팅 동기화** — 같은 방을 **메시지 단위**로 합칩니다. 각자 쓴 것이 남고, 한쪽에서
  지운 메시지는 다른 쪽에서도 지워집니다. 채팅이 바뀐 2분 뒤, 다른 PC 가 올렸으면 10분마다 맞춥니다
- 백업에서 **"AI 채팅"에 메신저 보관함이 딸려 가던 것**을 분리했습니다(813MB 라 업로드가 실패했습니다).
  300MB 가 넘는 항목은 크기와 함께 거절합니다. Google Drive 는 4MB 넘는 파일을 이어 올립니다
- **자동 백업**: 덮어쓰기 항목이 클라우드의 옛 사본을 로컬에 되돌려 놓던 것, 종료 때 600ms 만에 죽던
  것을 고쳤습니다. 항목마다 따로 시도하고 마지막 결과와 실패 이유를 옵션에서 볼 수 있습니다
