# v2.4.6

**설치와 제거를 손봤습니다.** 예전 버전을 작업표시줄에 고정해둔 채로 새로 설치하면 아이콘이
따로 잡히던 문제, 그리고 제거가 오래 걸리던 문제 두 가지입니다.

## 📌 작업표시줄에 고정해둔 아이콘

v2.4.3 이전 버전을 작업표시줄에 고정해둔 상태로 새 버전을 설치하면, **예전 고정 아이콘이 그대로
남아 실행하면 아이콘이 하나 더 생겼습니다.** 고정을 해제하고 새로 고정하면 정상이었습니다.

앱은 창에 자기 식별자(AUMID)를 붙입니다. 고정 바로가기에도 같은 값이 있어야 Windows 가
"고정 아이콘" 과 "실행 중인 창" 을 한 앱으로 묶는데, **v2.4.3 이전에 고정한 바로가기에는 그 값이
아예 없습니다.** v2.4.3 은 앱과 설치본이 새로 만드는 바로가기를 맞춘 것이라, 그 전에 이미
고정해둔 것은 손댈 수 없었습니다.

이제 **설치할 때 그 고정 바로가기를 찾아 새 설치본 것으로 고쳐 끼웁니다.**

- 고정 폴더의 바로가기를 열어 **가리키는 실행파일이 PePe 인 것만** 고릅니다 — 예전 설치 폴더가
  달라도 잡힙니다
- 대상 경로·작업 폴더·아이콘·식별자를 새 설치본 것으로 덮어씁니다. 고정 자체는 그대로 유지됩니다
- 이미 맞으면 건드리지 않습니다

> 고정을 프로그램으로 다시 하는 길은 Windows 가 막아뒀지만, 이미 고정된 바로가기 파일을
> 제자리에서 고치는 것은 됩니다. 회사 정책으로 스크립트 실행이 막힌 환경에서는 설치본이
> 이름으로 찾아 다시 만드는 방식으로 넘어갑니다.

## 🗑 제거가 오래 걸리던 문제

제거할 때 파일을 하나씩 지우며 그 경로를 계속 화면에 찍고 있었습니다. 큰 폴더들(X11 서버, JRE,
선택 설치 번들)은 원래 한 번에 지우고 있었는데 **네이티브 모듈 폴더가 그 목록에서 빠져
있었습니다.**

```
resources 전체              13,957개
  이미 한 번에 지우던 것       9,088개
  하나씩 지우던 것            4,869개
    그중 네이티브 모듈 폴더    4,631개  ← 나머지의 95%
```

이제 이 폴더도 한 번에 지웁니다 — 실측으로 **4,631개 / 205MB 를 1.3초**에 정리합니다. 하나씩
지우는 대상은 약 240개만 남습니다.
