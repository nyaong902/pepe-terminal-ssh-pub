# v2.3.6

새 워크스페이스 세 개, 설치할 기능을 골라 담는 기능, 그리고 커서 효과를 켜면 GPU 를 많이 쓰던
문제를 잡은 릴리즈입니다.

## 🗄 대화 아카이브 검색 — 새 워크스페이스

사내 메신저의 지난 대화를 로컬에 모아두고, **자연어로 물어서 관련 대화를 찾는** 워크스페이스가
추가됐습니다. 탭바 `+`, 도구 모음 바의 🗄 버튼, 명령 팔레트("대화 아카이브 검색")에서 열 수
있습니다.

- 키워드가 정확히 기억나지 않아도 됩니다 — "그거 말고 배포 지시문 쪽으로" 처럼 이어서 물어보면
  앞 대화를 이어받아 다시 찾습니다
- 방을 골라서 범위를 좁힐 수 있고, 아직 안 모은 지난 대화를 채우는 동안 진행률이 표시됩니다
- 찾은 대화는 **메신저 자체 검색창으로 넘겨줍니다.** 오래된 대화는 바로 스크롤해서 보여줄 수
  없지만, 메신저의 검색 결과로 진입해서 원문 맥락을 볼 수 있습니다
- 모아둔 대화는 로컬에 암호화해서 보관합니다

## 🔎 Pepe-Thing — 파일 검색 워크스페이스

PC 안의 파일과 폴더를 즉시 찾는 워크스페이스입니다. **voidtools Everything** 의 로컬 인덱스를
그대로 쓰기 때문에 별도 색인 작업 없이 바로 검색됩니다.

- 대소문자 구분 / 단어 단위 / 경로 포함 / 정규식 옵션
- 이름·경로·크기·수정한 날짜로 정렬
- 열기 / 폴더 열기 / 경로 복사
- Everything 이 설치되어 있지 않거나 실행 중이 아니면 안내와 다운로드 링크를 보여줍니다

> Everything 이 필요합니다. PePe 가 자체 색인을 만들지 않고 이미 있는 인덱스를 조회하는 방식이라,
> 수십만 개 파일에서도 입력하는 즉시 결과가 나옵니다.

## 📦 Pepe-Box — 클라우드 저장소 연동 (실험적)

Dropbox · Google Drive · OneDrive · 네이버 · 카카오를 연동해 클라우드 파일을 다루는 워크스페이스가
추가됐습니다. 각 서비스의 개발자 콘솔에서 앱을 만들고 Client ID 를 넣는 방식이며, 콘솔에서 어떤
항목을 어떤 순서로 설정해야 하는지 서비스별 안내가 화면에 함께 나옵니다(Redirect URI 등록 위치,
필요한 권한 항목, 흔한 오류의 원인까지).

> **아직 작업 중인 기능입니다.** 서비스에 따라 파일 탐색이 아니라 웹 화면으로만 표시되는 경우가
> 있고(공식 API 가 없는 서비스), 동작이 바뀔 수 있습니다.

## 🧩 설치할 기능 고르기

설치할 때 필요한 기능만 골라 담을 수 있습니다. 설치 화면에 항목별 설명과 용량이 함께 나오고,
다시 설치하면 지난번 선택이 기본값으로 잡힙니다. 해제한 기능은 메뉴에서도 보이지 않습니다.

| 항목 | 용량 |
|---|---|
| VPN 연결 | 약 9MB |
| MicroSIP · SSW 소프트폰 | 약 52MB |
| SIPp 부하테스트 | 약 14MB |
| 미디어 재생 (EVS/AMR/OPUS 코덱) | 약 14MB |
| 오피스 문서 편집 (한글·워드·PDF·플로차트) | 약 220MB |
| 대화 아카이브 검색 (AI 검색 런타임) | 약 158MB |
| SSW CDR 로그 분석 | 약 1MB |
| Pepe-Thing · Pepe-Box | 메뉴만 숨김 (용량 변화 없음) |

이번에 **대화 아카이브 검색 · Pepe-Thing · Pepe-Box** 가 선택 항목으로 추가됐습니다. 특히 대화
아카이브 검색은 자연어로 찾기 위한 AI 검색 런타임이 158MB 라서, 쓰지 않는다면 해제하는 편이
낫습니다.

> PePe 본체는 해제할 수 없습니다. 목록 맨 위에 회색으로 고정돼 있습니다.

## 설치 용량이 줄었습니다

기능은 그대로 두고 용량만 줄였습니다. 편집기·다이어그램·PDF 같은 라이브러리가 앱 안에 **두 벌씩**
들어가 있었습니다 — 화면을 그리는 쪽에서 이미 하나로 묶어 쓰고 있는데, 원본 파일 전체가 별도로 또
담겨 있었습니다.

| | 이전 | 현재 |
|---|---|---|
| 설치 파일 | 442 MB | **385 MB** |
| 설치 후 (전부 선택) | 약 1.57 GB | 약 **1.19 GB** |
| 설치 후 (대화 아카이브 해제) | — | 약 **1.01 GB** |

설치 화면에 표시되던 필요 용량도 실제와 맞게 고쳤습니다. 예전에는 MicroSIP 을 104MB, 미디어
재생을 49MB 로 안내했지만 실제로는 각각 52MB, 14MB 였습니다.

## 편집기가 인터넷 없이 동작합니다

SQL Tool · 파일 편집기 · 파일 비교 · 객체 상세에서 쓰는 편집기가 열릴 때마다 **외부 CDN 에서
편집기 엔진을 받아오고 있었습니다.** 사내망처럼 외부 접속이 막힌 곳에서는 이 편집기들이 전부 빈
화면이 됐습니다. 이제 앱 안에 담아서 씁니다.

## MicroSIP 을 해제해도 설치되던 문제

MicroSIP 과 SSW 소프트폰은 같은 통화 엔진을 공유합니다. 그래서 SSW 소프트폰 때문에 엔진이 깔리면
MicroSIP 을 해제해도 메뉴에 그대로 나타났습니다. 이제 설치할 때 고른 대로 동작합니다.

## 파일을 미디어 / 오피스 워크스페이스에서 바로 열기

파일 전송, 파일 트리, Pepe-Thing 어디에서든 파일을 더블클릭하면 PePe 안에서 열립니다.

- `wav` `amr` `evs` `opus` 등 음성 파일 → 미디어 워크스페이스에서 재생
- `hwp` `hwpx` `docx` `xlsx` `pptx` `pdf` → 오피스 워크스페이스에서 열기
- 물어보는 창에서 "아니오" 를 고르면 시스템 기본 프로그램으로 엽니다

## SQL Tool — 다단계 SSH 점프 체인

SQL Tool 이 자체 DB 연결 세션으로 분리되면서 SSH 터널이 **단일 홉만** 지원하게 됐던 것을
복구했습니다. 이제 DB 세션 편집 화면에서 중간에 거칠 게이트웨이를 여러 단계로 등록할 수 있습니다 —
터미널 세션 편집기의 점프 체인과 같은 방식입니다.

## 커서 효과를 켜면 GPU 를 많이 쓰던 문제

세션 > 모양 > 커서에서 프리즘·불꽃·별·하트·동그라미·무지개·파워를 쓰면 GPU 사용률이 크게
오르고, 불꽃과 무지개는 앱 자체가 버벅이기까지 했습니다. 원인이 하나가 아니라 넷이었습니다.

작업 관리자 GPU 사용률 기준, 같은 강도로 연속 타이핑하며 측정한 결과입니다
(일반 블록 커서가 1.5%, 세로로 엔터를 연타하는 최악 조건이 3%):

| 조건 | 이전 | 현재 |
|---|---|---|
| 불꽃 · 가로로 타이핑 | 9.5% | **4% 내외** |
| 파워 · 가로로 타이핑 | 12% | **5% 내외** |
| 불꽃 / 파워 · 엔터 연타 | 9.2% / 12% | **7.8%** |

버벅임도 사라졌습니다 — 86초 측정에서 드롭된 프레임이 48개뿐입니다.

- **이모지를 매 프레임 다시 그리던 문제** — 🔥 나 🌈 같은 컬러 이모지를 파티클마다 매 프레임
  래스터화하고 있었습니다. 측정해보니 그 하나가 렌더러 작업 시간의 87% 였습니다. 이제 같은
  (모양·크기·색) 조합을 한 번만 그려두고 복사해서 씁니다. 파티클이 동시에 너무 많이 쌓이지
  않도록 상한도 함께 두었습니다
- **캔버스가 터미널 전체를 덮고 있던 문제** — 파티클을 그리는 캔버스가 터미널 크기와 같아서,
  파티클이 몇 개뿐이어도 화면 전체를 다시 합성하고 있었습니다. 이제 커서 주변만 덮고
  커서를 따라 움직이며, 그 높이는 커서 효과마다 파티클이 실제로 날아가는 거리를 계산해서
  정합니다. 파티클이 다 사라지면 캔버스를 아예 치워 타이핑을 쉬는 동안은 비용이 없습니다
- **파워 커서의 화면 흔들림** — 흔들림이 터미널 전체를 매 프레임 다시 그리게 만들고 있었습니다.
  이제 흔들리는 동안 화면을 별도 레이어로 올려 옮기기만 하고, 흔들림 폭도 1px 단위로 끊어
  글자가 흐려지지 않습니다
- **프리즘 커서** — 색을 바꾸려고 터미널 테마 전체를 초당 20회 갈아끼우고 있었습니다. 그때마다
  모든 색을 다시 계산하고 전체 화면을 새로 그렸습니다. 이제 커서 색만 직접 바꿉니다

겉모습은 그대로입니다. 파티클이 날아가는 거리·속도·수명·잔상 모두 이전과 같은지 픽셀 단위로
대조해서 확인했습니다.

## 아무것도 안 하는데 GPU 사용률이 계속 움직이던 문제

창을 두 개 띄우고 터미널만 열어둔 채 아무 작업도 하지 않아도 GPU 사용률이 계속 오르내렸습니다.

패널 우측 상단의 활성 표시 점이 원인이었습니다. 점이 커졌다 작아지고 후광이 밝아졌다
어두워지는 애니메이션이 멈추지 않고 돌면서, 화면에 변화가 없어도 매 프레임 그림을 다시 만들게
하고 있었습니다. 65초 동안 재보니 초당 70회 다시 그리고 있었습니다. 패널마다 하나씩이라
창 2개 × 터미널 2개면 그게 네 배가 됩니다.

후광은 그대로 두고 깜빡임만 멈췄습니다 — 활성 상태를 표시한다는 목적은 그대로입니다.

## vimdiff 를 나오면 셸 출력이 초록색으로 물들던 문제

원격에서 `vimdiff` 를 빠져나오면 그 뒤 셸 출력 전체가 초록 배경으로 칠린 채 남고, `ls` 처럼
색을 쓰는 명령이 나올 때까지 계속되던 문제를 잡았습니다. 매번은 아니고 간헐적이었습니다.

vim 의 상태줄 색이 셸로 새어나온 것이었습니다. vim 같은 전체화면 프로그램은 전용 화면으로
전환해서 그리고 나올 때 원래 화면을 복원하는데, 이 서버의 vim 이 나오면서 글자색·배경색을
되돌려주지 않아 그 상태가 그대로 남았습니다. 이제 전용 화면에서 빠져나오는 시점에 색 상태를
초기화합니다.

> 이런 증상이 또 보이면 `printf '\033[m'` 로 즉시 되돌릴 수 있습니다.

## 브라우저 워크스페이스

하위 탭이 많아지면 탭바에 굵고 지저분한 가로 스크롤바가 나타나던 문제를 고쳤습니다.
파일전송 패널의 탭바와 같은 방식으로 바꿨습니다 — 넘칠 때 `‹ ›` 버튼이 나타나고, 마우스 휠로도
좌우로 넘길 수 있습니다. `‹ ›` 와 `+` 는 오른쪽에 고정되어 탭이 많아도 밀려 사라지지 않습니다.

탭 제목도 이전에는 80px 까지 찌그러진 뒤에야 넘쳐서 제목이 전부 `about…` 으로 뭉개졌는데,
이제 읽을 수 있는 폭을 유지한 채 넘어갑니다.
