**PePe TV 가 들어왔습니다.** 실시간 채널을 앱 안에서 바로 보고, 설치가 필요 없는 별도
포터블 플레이어도 함께 나갑니다. 그리고 AI 챗에서 "대화가 끊긴 것처럼 보이던" 문제들을
하나씩 걷어냈습니다 — 표시가 사라지던 것, 도구 목록이 잘리던 것, 목록이 창 절반에서
끝나던 것.

## 📺 PePe TV

- **실시간 채널** — 목록·검색·즐겨찾기(★ 로 위에 고정), HLS 재생. 재생이 안 되는 채널은
  목록에서 스스로 빠집니다
- **독립 실행 플레이어** — 설치 없이 실행하는 포터블 EXE 를 따로 냅니다. Electron 과 재생
  엔진을 안에 담고 있어 별도 설치가 필요 없습니다(Windows / macOS / Linux 타깃)
- **SBS 인증 재생** 추가, 채널 목록 갱신. 응답에 여러 스트림이 오면 **화질·비트레이트가 가장
  높은 것**을 고릅니다
- **재생이 시작됐는데 "연결 중" 가림막이 남아 있던 문제**

### VOD 브라우저 — 광고를 걷어내고 봅니다

독립 플레이어에 **WebView2 기반 VOD 브라우저**를 넣었습니다. 다시보기를 앱 안에서 바로
열고, 광고·추적 도메인 36종을 네트워크 단계에서 막고 페이지 안에 남는 자리까지 정리합니다
(유튜브는 재생 응답에서 광고 슬롯 자체를 들어냅니다). 크롬을 쓰는 경로에서는 같은 규칙을
디버깅 프로토콜로 밀어 넣어 동일하게 동작합니다.

## 🤖 AI 챗

### 대화가 끊긴 것처럼 보이던 문제 — 두 겹이었습니다

> "생각중 표시가 나오다가 없어지면서 대화가 끊겨. 끊겨있다가 한참 뒤에 응답 결과는 와."

렌더러에는 스트림 감시 타이머가 있습니다 — 이벤트가 한동안 없으면 "에이전트가 아직 살아
있는지" 물어보고, 아니라고 하면 진행 표시를 내립니다(응답이 영원히 도는 것을 막는 장치).

1. **살아 있어도 항상 "죽었다" 고 답했습니다.** 생존 확인이 claude/gemini/codex 맵만 보는데,
   Claude+ 는 세션당 장기 프로세스를 별도 레지스트리에서 관리해 그 맵에 없었습니다. 이제
   그쪽도 함께 봅니다 — 요청 번호를 주면 그 요청을 맡은 인스턴스만 확인해서, 다른 대화가
   도는 것을 살아있다고 오판하지 않습니다
2. **감시 기준이 하트비트 간격보다 짧았습니다.** CLI 는 오래 걸리는 도구가 돌 때 30초마다
   하트비트를 보내는데 기준이 12초였습니다 — 긴 도구 실행마다 반드시 이 검사에 걸렸습니다.
   기준을 40초로 올렸습니다. 하트비트만으로도 살아 있는 것이 드러나므로 생존 확인에
   기대지 않습니다(콜드스타트 90초 기준은 그대로)

### 도구 사용 목록

- **아래가 잘려 보이던 문제** — 접힌 그룹이 **높이 2px(내용 29px)** 로 눌려 헤더까지
  잘렸습니다. 대화 영역이 flex 컬럼이면서 스크롤되니 자식들이 줄어들 수 있고, 그중
  `overflow` 가 걸린 요소는 "자동 최소 크기" 가 0 이 되어 내용과 무관하게 납작해집니다.
  스크롤되는 목록에서는 어느 자식도 눌릴 이유가 없으므로 통째로 막았습니다
  (실측: 고치기 전 2px → 고친 뒤 31px, 내용 29px)
- **도구가 도는 동안 목록이 저절로 펼쳐지고 접기가 안 되던 문제** — 펼침 판정에 "실행 중이면
  펼친다" 가 붙어 있어서, 접어도 그 조건이 계속 참이라 다시 열렸습니다. 이제 사용자가 누른
  상태만 따릅니다. 접힌 채로도 ⏳ 아이콘과 "읽기 7개, 검색 2개" 요약으로 진행이 보입니다

### 대화 목록

- **목록이 창 절반에서 끊기던 문제** — 목록을 볼 때 안쪽 메시지 영역과 입력창은 숨는데
  그것들을 담은 컨테이너만 남아, 이력 패널과 높이를 반씩 나눠 가졌습니다
  (실측: 600px 사이드바에서 목록이 325px 에서 끝남 → 이제 바닥까지)
- **목록을 한 번 클릭한 것만으로 "새 대화 - COPIED" 가 생기던 문제** — 이미 열린 탭인데
  포커스가 아니면 "하나 더 열고 싶다는 뜻" 으로 해석하고 있었습니다. 이제 그 탭으로
  이동만 합니다. 복제는 목록 행의 **⧉** 버튼으로만 — 의도한 사람만 누릅니다
- 자동 제목을 60자에서 200자로 — 경로처럼 앞부분이 같은 질문들이 같은 자리에서 잘려 네 줄이
  똑같이 보였습니다
- Claude 와 Claude+ 를 목록에서 같은 자리로 취급 — Claude+ 를 켠 뒤에 예전 대화가 목록에서
  빠지지 않습니다. 한 대화에 아이콘이 두 개 붙던 것도 정리

### 대화 탭

- **가운데 클릭으로 닫기** — 워크스페이스 탭바와 같은 동작입니다
- **탭이 4개일 때 `+` 를 누르면 조용히 아무 일도 없던 것** — `+` 버튼 바로 위에 작은
  말풍선으로 이유를 알리고 2.6초 뒤 사라집니다. 버튼 클릭을 가로막지 않습니다

### 분할 보기 — 창을 전환해도 화면이 그대로입니다

선택하지 않은 창은 스크롤이 맨 위로 튀고, 다시 선택하면 맨 아래로 내려갔습니다. 전환할 때마다
화면이 **번쩍이기도** 했습니다.

원인은 스크롤이 아니라 **다시 그리기**였습니다. 포커스를 잃는 순간 그 대화는 별개 요소로
새로 마운트돼서, 마크다운·코드 색칠·다이어그램을 처음부터 다시 그렸습니다. 그 사이 높이가
계속 변하니 화면이 흔들리고, 새 요소라 스크롤도 0(맨 위)에서 시작했습니다.

이제 **대화마다 자기 창을 그대로 두고 포커스만 옮깁니다.** 전환해도 다시 그리지 않고, 보던
자리가 그대로 있습니다.

> 창이 실제로 새로 열리는 경우(단일 보기에서 대화 전환 등)에는 위치를 되돌리는데, 이때도
> 픽셀이 아니라 "화면 맨 위에 있던 글" 을 기준으로 잡습니다. 다시 그리는 동안 위쪽 높이가
> 변하면 같은 픽셀 값이 매 순간 다른 글을 가리키기 때문입니다.

### 그 밖에

- **mermaid 코드블록이 `Tri1 ~~~ Tri2` 줄에서 끊기던 문제** — 그 줄만 별도 상자가 되고 뒤의
  `end`·`style …` 이 맨글자로 나왔습니다. fence 를 빼먹는 모델을 대비한 전처리가 투명 링크
  `~~~` 를 mermaid 문법으로 몰라봐서 산문으로 오인한 것이었습니다. 빠져 있던 연산자를
  채웠습니다(`~~~` `~~` `<--` `<-.` `<==` `o--` `x--`)
- **다이어그램이 미완성 상태로 그려지고 남은 줄이 글자로 새던 문제** — 받아쓰는 중인
  말풍선의 블록은 다 받은 뒤에 한 번에 그립니다
- **git 바가 대화와 무관한 저장소를 보던 문제** — 잡담만 한 대화에도 `⎇ main +2 -2` 와 PR
  생성 버튼이 떴는데, 그 숫자는 **앱을 실행한 디렉터리**(개발 중이면 PePe 자기 소스)의
  상태였습니다. 설치본에서는 반대로 이 바가 아예 뜨지 않았습니다. 이제 그 대화가 다루는
  경로를 기준으로 봅니다
- **SSH 컨텍스트 줄**은 AI 탭에서만 보입니다(메신저·작업일지에서는 감춥니다)

## 🖱 워크스페이스 탭

**새 탭에 색이 제멋대로 붙던 것을 없앴습니다.** 탭을 만들 때마다 무작위로 색을 골라 배정하고
있었습니다. 이제 기본 색으로 만들어지고, 색은 **우클릭 메뉴에서 직접** 고릅니다.

## 📁 파일 전송

**이미 선택된 항목을 한 번 더 클릭하면 이름변경**으로 들어갑니다 — 탐색기의 "느린 더블클릭"
관례입니다(`F2` 와 같은 동작). 빠른 더블클릭(열기·폴더 진입)과 겹치지 않게, 더블클릭 판정보다
넉넉히 기다렸다가 실제 더블클릭이 오면 예약을 취소합니다.

## 🗂 파일트리 — 이전/다음/상위 폴더

경로바에 있던 것은 이동(`↵`) · 현재 경로에 업로드(`⬆`) · 새로고침(`⟳`) 뿐이라, 폴더를 오간 뒤
**되돌아갈 방법이 없었고 상위로 올라가는 버튼도 없었습니다.** 파일전송 패널과 같은 배치로
맞췄습니다.

```
← → [ /SI/SSW/log/jhpark ] ↵ ↑ ⟳
```

- **이전/다음 폴더** — 기록 50개까지, 끝에 닿으면 흐리게 비활성. 탭을 떠났다 돌아와도 유지
- **상위 폴더** — 원격은 posix, 로컬은 Windows 경로를 따로 처리합니다(`C:\Users` 위는 `C:\`)
- **업로드는 헤더의 📄 📁 옆으로** 옮겼습니다. 경로바는 탐색 전용입니다

> 기록에는 사용자가 직접 옮긴 경로만 쌓습니다. 접속 과정에서 거쳐가는 홈 폴백(`/`) 같은
> 경로까지 넣으면, 가본 적 없는 곳이 "이전 폴더" 에 남습니다.

## 🖥 터미널

**텍스트를 골라둔 뒤 스크롤바를 건드리면 선택이 풀리던 문제.** 스크롤바도 뷰포트의
일부라서, xterm 이 그 클릭을 "새 선택 시작" 으로 보고 기존 선택을 지웠습니다. 스크롤바
영역에서 시작한 클릭만 걸러냅니다 — 브라우저 기본 스크롤바 드래그는 그대로입니다.

## 🪟 Ctrl+N 으로 AI 챗을 열면 우측 사이드바가 사라지던 문제

한 증상에 원인이 네 개 겹쳐 있었고, 제보자가 콘솔로 재준 값이 매번 다음 겹을 가리켰습니다.

1. **토글 판정이 "마운트됐는가" 만 봤습니다.** 자동 숨김으로 쓰면 화면에서 숨어 있어도 그
   값은 참이라, 열려고 눌렀는데 "이미 열려 있다" 며 닫아버렸습니다
2. **숨김 예약 타이머가 살아 있었습니다.** 마우스가 벗어나면 500ms 뒤 숨기는데, 그 사이에
   Ctrl+N 을 누르면 떴다가 예약대로 사라졌습니다. 마우스 쪽 핸들러 6곳은 이 타이머를
   정리하는데 키보드 경로만 빠져 있었습니다
3. **키를 누르고 있으면 자동 반복이 토글을 계속 뒤집었습니다.** 닫을 때 두 상태를 함께
   내리도록도 고쳤습니다 — 한쪽만 내리면 "숨김 클래스는 없는데 화면에는 없는" 어긋난
   상태가 남습니다
4. **진짜 이유는 22px 이었습니다.** 우측 트리거 줄 자리를 예약하는 클래스의 조건이 트리거를
   그리는 조건과 달라서, 패널을 닫는 순간 예약만 풀리고 콘텐츠가 22px 넓어지며 트리거 줄을
   덮었습니다. 사이드바가 사라진 것처럼 보인 것은 이것이었습니다

5. **고정(pin)한 채로 닫으면 우측이 통째로 비었습니다.** 트리거 줄이 "고정이 아닐 때" 만
   그려지고 있었습니다 — 고정한 상태에서 Ctrl+N 으로 닫으면 패널도 트리거도 없어져 돌아올
   길이 툴바 버튼뿐이었습니다. 이제 **패널이 화면에 없으면 트리거는 항상** 그립니다
