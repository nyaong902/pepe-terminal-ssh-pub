# v2.6.4

**Pepe-Code**(VS Code 워크스페이스), **텔넷 접속**, **AI Chat 대화방 저장소**가 새로
들어갔습니다. 접속이 아예 안 되던 SSH 문제와 한글 파일 이름이 깨지던 문제도 고쳤습니다.

## 🧑‍💻 Pepe-Code — 앱 안에서 VS Code 로 서버 파일 편집

SSH 세션에 붙은 서버의 파일을 **VS Code 그대로** 열어 고칩니다. 따로 설치하거나 서버에
무언가를 올릴 필요가 없습니다 — 이미 맺어 둔 SSH/SFTP 연결을 그대로 씁니다.

- **파일 열기·검색이 서버 전체를 대상으로** 동작합니다. `Cmd+P` 로 바로 열고,
  `Cmd+Shift+F` 로 내용을 찾습니다(서버에서 직접 `find`/`grep` 을 돌립니다)
- **통합 터미널**은 그 SSH 연결 위에 새 셸을 엽니다 — 세션에 적어 둔 ClearCase 뷰와 rel 이
  자동으로 들어갑니다
- **ClearCase** 를 쓰는 서버라면 체크아웃/체크인을 편집기 안에서 합니다. 파일마다 CO/CI 와
  CR 번호가 배지로 붙고, 버전 목록(`lsvtree`)과 버전 간 비교, `ctunco` 까지 됩니다.
  체크인은 체크아웃할 때 쓴 CR 번호를 자동으로 가져다 씁니다
- 커스텀 워크스페이스 슬롯에서도 고를 수 있고, 탭을 **"우측에 함께 보기"** 로 나란히 둘 수
  있습니다

code-server 는 용량이 커서(약 630MB) **선택 설치 항목**입니다. 설치할 때 체크하면 들어가고,
한 번 체크해 두면 다음 업데이트에서도 유지됩니다. 포터블판은 Pepe-Code 를 처음 열 때
알아서 풀립니다.

## 🔌 텔넷 접속

접근통제 솔루션처럼 텔넷으로만 닿는 장비가 있는데, 지금까지는 자산관리툴이 앱을
`telnet://host:port` 로 띄우는 경로에서만 접속됐습니다. **손으로 고를 길이 없었습니다.**

- **세션 편집 > 연결**에 접속 방식 드롭다운이 생겼습니다(포트도 22↔23 으로 따라갑니다).
  **빠른연결** 바에도 Telnet 이 생겼습니다
- 아이디·비밀번호와 **로그인 스크립트**를 그대로 씁니다. 접근통제 장비의 메뉴처럼 여러 번
  묻는 화면도 규칙을 적어 두면 넘어갑니다
- **AI Chat 과 파일트리·파일비교·로그분석이 텔넷에서도 동작합니다.** 텔넷에는 SFTP 가 없어
  셸로 목록을 받아 오고, AI 가 쓸 **전용 연결을 따로** 엽니다 — AI 가 돌린 명령과 그 출력이
  사용자 터미널 화면에 섞이지 않고, 타이핑도 막히지 않습니다
- 파일트리가 **현재 경로를 따라갑니다.** 프롬프트에서 경로를 읽는 부분이 `user@host` 꼴만
  알아봐서, `[cube(view):/vobs/...]` 처럼 사용자 이름이 없는 프롬프트를 놓치고 있었습니다
- 세션에 지정한 **인코딩이 메뉴에도 그대로** 보입니다(해석은 처음부터 맞게 하고 있었는데,
  메뉴만 늘 UTF-8 로 보였습니다)

## 🤖 AI Chat — 대화방마다 따로, 그리고 이어서

대화가 **방 단위로 따로 보관**됩니다. 방마다 자기 폴더를 갖고 대화·첨부·색인을 그 안에
둡니다. 첨부 파일은 같은 파일이면 한 번만 저장하고, 방의 저장 용량이 한도를 넘으면 오래된
것부터 비웁니다.

- **이어서 대화하기.** 설정을 바꿔 다시 띄우거나, 중단했다가 앱을 껐다 켜도 **하던 대화를
  그대로 이어갑니다**
- **서브 세션.** 돌고 있는 대화를 새 탭으로 갈라 **둘을 동시에** 돌릴 수 있습니다(Claude 전용)
- **다른 방 참조.** 선택창에서 고르거나 요청에 방 제목을 적으면 그 방의 내용을 끌어옵니다
- **여러 개 골라 한 번에 삭제.** 대화 이력 목록을 열면 검색줄 아래에 **전체 선택 / 선택 삭제**
  가 나옵니다. 지금 목록에 보이는 것만 고르므로, 검색 중이면 검색 결과만 대상이 됩니다
- **Pepe-Code 워크스페이스를 AI 의 작업 대상으로** 지정할 수 있습니다. 그 폴더를 기준으로만
  파일을 보게 범위가 묶입니다(ClearCase 뷰도 함께 인식합니다)

## 🩺 SSH — 한참 쓰다 보면 접속이 아예 안 되던 문제

오래 쓰다 보면 등록된 세션 접속이 `Worker terminated due to reaching memory limit` 로
실패했습니다. 같은 서버를 앱 안의 파워쉘에서 `ssh` 로는 붙을 수 있고, **앱을 껐다 켜면
다시 됐습니다.**

연결이 끊어질 때 터미널 작업 스레드를 **정리하지 않고 참조만 버리고 있었습니다.** 연결은
죽었지만 스레드는 살아서 메모리를 쥔 채 남고, 재접속할 때마다 하나씩 늘었습니다. 자동
재접속이 도는 환경에서는 조용히 쌓이다가 어느 순간 새 연결을 못 만들게 됩니다.

이제 연결이 끝나면 스레드도 확실히 정리하고, 새로 만들기 전에 남은 것이 있으면 먼저
거둡니다. 접속이 핸드셰이크에서 실패하면 **어느 단계에서 막혔는지** 알려줍니다.

## 🔁 재연결 중인 탭을 다른 세션이 덮어쓰던 문제

장비가 내려가 **"다시 연결하는 중....."** 으로 재시도를 돌고 있는 탭이 있을 때, 다른 세션을
더블클릭하면 **새 탭이 아니라 그 탭에서** 연결을 시도했습니다. 원래 있던 세션이 밀려나고,
새로 고른 세션도 붙지 않았습니다.

"이 탭이 쓰이고 있나" 를 보는 판정에 **자동 재연결 루프가 빠져 있었습니다.** 재시도는
시도와 시도 사이에 잠깐 비는데, 하필 그 순간에는 빈 탭으로 보였습니다. 이제 재시도 중인
탭도 사용 중으로 보고 **새 미니탭**으로 엽니다.

## 📁 파일전송 — 한글(EUC-KR) 파일 이름이 깨지던 문제

파일전송 화면에서 한글 이름이 `KT-C4SSW-DB_CDR ???8? ???U?...` 처럼 보이고, 인코딩을
EUC-KR 로 바꿔도 그대로였습니다. 터미널에서는 멀쩡하게 보여서 더 이상했습니다.

인코딩 설정 문제가 아니었습니다. SFTP 가 파일 이름을 받자마자 UTF-8 로 해석해 버려서
**그 자리에서 원래 바이트가 사라집니다** — 뒤에서 무엇을 고르든 되살릴 수 없습니다.
그래서 이름이 필요한 곳은 SFTP 대신 **셸에서 목록을 받아** 고른 인코딩으로 읽습니다.

> UTF-8 이 아닌 이름의 파일을 **주고받는 것**은 아직 안 됩니다(지금까지도 안 됐습니다).
> 이름이 제대로 보이는 것까지가 이번 변경입니다.

## 🚪 앱 종료 확인

앱을 끌 때 **"종료하시겠습니까?"** 를 한 번 묻습니다. 마지막 창을 닫아 **앱이 실제로
끝날 때만** 묻습니다 — 창을 여러 개 띄워 두고 그중 하나를 닫는 것은 앱을 끝내는 것이
아니므로 묻지 않습니다.

매번 뜨는 것이 번거로우면 끌 수 있습니다.

- 확인창의 **"다음부터 묻지 않기"** 체크박스
- **옵션 > 터미널 > 앱 종료**에서 켜고 끄기

## ✨ 그 밖에

- **파일 비교** 목록에 ClearCase 체크아웃 상태와 CR 번호가 표시됩니다
- **AI Chat 대화 탭**에 가로 스크롤바가 드러나 있던 것을 없애고, **마우스 휠**로 넘기게
  했습니다. 탭이 넘치면 `‹ ›` 가 뜨고, **모든 탭** 목록에서 바로 고를 수 있습니다
- **스티커 메모 목록**이 화면의 위쪽 절반에만 그려지던 것을 고쳤습니다. 카드가 줄 중간에서
  잘려 글자 아랫부분이 날아가던 것도 함께 고쳤고(미리보기 세 줄), 카드의 `⋯` 버튼은 경계가
  보이게 해서 **어디를 누르면 스티커 창이 뜨고 어디를 누르면 메뉴가 뜨는지** 분명해졌습니다
- **사내 메신저** 저장된 계정을 삭제할 수 있고(두 단계 확인), 우측 패널에서 로그인/로그아웃을
  토글할 수 있습니다
