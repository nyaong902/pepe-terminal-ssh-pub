# v2.3.5

## SSW CDR 로그 분석 — 새 워크스페이스

SKB SSW 의 Call Log(Clog) 와 CDR(C5) 원문을 붙여넣거나 파일/SSH 로 가져와 필드별로 풀어보는
워크스페이스가 추가됐습니다. 탭바 `+` → 워크스페이스, 도구 메뉴, 명령 팔레트에서 열 수 있습니다.

- **Clog 탭** — 121개 필드를 섹션별로 펼쳐 보여주고, CallID 기준으로 발신/착신 레코드를 짝지어
  묶습니다. Q.850 원인값·Fail Code·Diameter 결과코드는 코드의 의미를 함께 표시합니다
- **CDR 탭** — 238바이트 고정폭 원문을 36개 필드로 분해합니다. 입력 길이가 규격에 맞는지
  즉시 알려주고, Clog 와 서로 연관된 필드는 `↔` 로 표시해 양쪽을 대조할 수 있습니다
- **참조 탭** — SuppSvcUse/AinSvcUse 필드 구조와 부가서비스 Type 코드표
- Clog / CDR 결과를 각각 Excel 로 내보낼 수 있습니다

### 데이터 가져오기 — 파일 또는 SSH 세션

파일 선택 외에, **이미 접속해 있는 SSH 세션에서 원격 파일을 바로 가져올** 수 있습니다.
세션 목록에서 고르고 경로만 입력하면 됩니다 — 새로 접속하지 않고 기존 연결을 그대로 씁니다.

- **실시간** 버튼 — 같은 파일을 5초마다 다시 읽어, 내용이 실제로 바뀐 경우에만 다시 분석합니다
- Clog / CDR 탭이 각각 독립적으로 동작해서 서로 다른 파일을 동시에 볼 수 있습니다
- 수백~수만 줄을 가져와도 입력창에는 앞 몇 줄만 미리보기로 남기고, 분석은 가져온 원문 전체로
  합니다 — 입력창이 데이터로 가득 차 화면을 잡아먹지 않습니다

### 결과 그리드 — SQL Tool 과 같은 조작

- **컬럼별 검색** — 헤더 아래 입력칸에 넣으면 해당 컬럼으로 걸러집니다(여러 컬럼은 AND).
  Clog 는 CallID 그룹 구조를 깨지 않도록 조건에 맞는 레코드가 있는 그룹만 남깁니다
- **컬럼 정렬** — 헤더를 누르면 오름차순 → 내림차순 → 해제. 값이 전부 숫자면 숫자로 정렬합니다
- **컬럼 고정(📌)** — 좌측에 고정해두고 가로 스크롤할 수 있습니다. 고정한 컬럼이 여러 개여도
  한 번에 해제하는 버튼이 결과 헤더에 나타납니다
- **컬럼 폭 조절** — 헤더 경계를 드래그(더블클릭하면 기본값)
- **결과창 크기 조절** — 결과창 위쪽 경계를 끌어 위/아래로. 헤더를 클릭하면 최대 ↔ 절반 ↔ 닫힘

### 선택 설치

설치 프로그램의 기능 선택 화면에서 이 도구만 빼고 설치할 수 있습니다(약 1MB). 선택하지 않으면
메뉴에도 나타나지 않으며, 선택은 다음 업데이트에도 유지됩니다.

## ClearCase 파일트리가 열리지 않던 문제

로그인 스크립트가 없는 세션에서 ClearCase 개발서버의 `/vobs` 파일트리가 열리지 않던 문제를
잡았습니다. **같은 세션에 로그인 스크립트를 넣으면 되던 것**이 단서였습니다.

`/vobs` 경로는 뷰 루트(`/view/<태그>`)를 알아야 접근되고, 그 정보는 터미널 프롬프트에서 읽습니다.
그런데 점프호스트도 로그인 스크립트도 없는 단순 연결은 성능을 위해 별도 워커 스레드로 처리되는데,
**그 경로에만 프롬프트 해석이 빠져** 있어서 뷰 태그를 영원히 알아낼 수 없었습니다.

- 워커 연결 경로에도 프롬프트 해석을 추가 — 뷰 태그와 셸 추적이 함께 복구됩니다
- 파일트리 첫 로드가 `/vobs` 경로면 뷰 정보가 잡힐 때까지 기다립니다. 예전에는 2.5초만 시도하고
  포기해서, 프롬프트가 조금 늦게 오는 PC 에서는 트리가 아예 안 열렸습니다
- 진단 로그 보강 — 뷰 루트를 **못 찾은** 경우에도 이유가 남고, 그 로그가 개발자 도구에서 보입니다
  (예전에는 메인 프로세스 콘솔로만 나가서 확인할 수 없었습니다)

> 참고: PowerShell 안에서 `ssh` 명령으로 직접 접속한 경우는 파일트리·파일전송이 동작하지 않습니다.
> 앱이 소유한 SSH 연결이 아니라서 파일을 읽을 통로가 없습니다 — 빠른 연결이나 세션 등록을 이용하세요.

## SQL Tool

- **SSH 터널 연결 시 앱이 종료되던 문제 수정** — SQL Tool 은 자체 SSH 접속 정보를 갖는데도,
  같은 호스트로 연결된 아무 터미널의 연결을 재사용하려 했습니다. 그 터미널이 워커 스레드 연결이면
  포트 포워딩을 지원하지 않아 DB 트래픽이 오는 순간 메인 프로세스가 죽었습니다. 이제 항상 터널
  설정에 입력한 정보로 전용 연결을 맺습니다
- **드라이버 관리자 창을 클릭하면 닫히던 문제 수정** — DB 세션 편집 화면 위에 열린 드라이버
  관리자를 클릭하면 그 클릭이 아래 편집기까지 전달돼 편집기가 닫히고, 딸려 있던 드라이버 관리자도
  같이 사라졌습니다
